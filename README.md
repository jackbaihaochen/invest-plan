# 1億円プロジェクト

攒到 1 亿日元的投资进度看板 —— 自动从 Gmail 里读取楽天証券的通知邮件，
计算真实的资产曲线，并督促你保持每月定投。

有**两个版本**，共用同一套解析与预测代码（`src/Shared.gs`，49 项测试覆盖）：

| | Track 1 · Artifact 看板 | Track 2 · Apps Script |
|---|---|---|
| 部署 | **零配置**，打开链接即可 | 需要约 15 分钟手动设置 |
| 数据来源 | 页面直接调用你的 Gmail / Drive 连接器 | 服务端定时抓取 |
| 投信（大头） | 实时 | 实时 |
| 股票 / 汇率 / BTC | 经 Google Sheet 的 GOOGLEFINANCE | 全自动 |
| 邮件督促 | 无 | 周报 + 月报 |
| 适合 | 现在就想用 | 想要全自动和邮件提醒 |

Track 1 已经发布可用。Track 2 的代码在 `src/`，随时可以部署，见下方安装步骤。

## Track 1 · Artifact 看板

页面通过 `mcp` 运行时能力调用**你自己的** claude.ai 连接器，用你的凭据读数据，
token 不会暴露给页面。首次同步会把算好的历史固化进页面自身的新版本，
之后打开是秒开，只增量拉取新邮件。

**你要做的三件事**（都在同一次访问里完成）：

1. 打开 `1億円プロジェクト — データ` 这张 Google 表格
2. 在 **B3** 粘贴这一行公式并回车 —— 6 个行情一次到位：
   ```
   =MAP(A3:A8,LAMBDA(t,IFERROR(GOOGLEFINANCE(t),0)))
   ```
3. 填 `野村持株会_評価額`、`ゆうちょ_残高`，以及持有的股数

然后回到看板点「最初の同期を実行」。

> 为什么公式要你自己贴：Drive API 建表时会丢弃公式（实测 `=1+1` 都存不进去），
> 所以这一格必须在 Sheets 界面里输入一次。`MAP`/`LAMBDA` 让它只需要一格。

> **不需要 bitFlyer API key。** BTC 数量已从你的交易记录算出（0.061912），
> 价格走 GOOGLEFINANCE。API secret 不该出现在聊天记录或代码库里。

```bash
npm run build     # 生成 build/dashboard.html
npm test          # 49 项测试
```

## 它解决的问题

楽天証券没有面向个人的公开 API。但它**每个工作日都会给你发一封「投信基準価額メール」**，
每次积立成交也会发「約定メール」。这两类邮件加起来，足以完整重建你的投信持仓，
不需要爬虫，不违反利用規約。

| 账户 | 获取方式 | 频率 |
|---|---|---|
| 楽天証券 投資信託 | 「投信基準価額メール」＋「積立購入が完了（約定）」邮件 | 每个工作日 |
| 楽天証券 株式 | Sheets 的 `GOOGLEFINANCE()` | 每天 |
| bitFlyer | 只读 API key（Assets 权限） | 每天 |
| 野村證券（持株会） | 手动录入（无 API，季度看残高明細書） | 你更新时 |
| ゆうちょ銀行 | 手动录入（参照系 API 仅限电子决済等代行業者） | 你更新时 |

> ゆうちょ的入金通知邮件**不含金额**，所以无法自动化；持株会同理。
> 这两个账户超过 60 天没更新，看板上会标红提醒。

## 看板上有什么

**核心指标不是进度条，而是「你落后了多久」**：

```
按当前实际节奏（近6个月平均 15万円/月）  →  2043年7月（16年11ヶ月）
                    落后 6年6ヶ月
按计划（40万円/月）                      →  2036年12月（10年5ヶ月）
```

除此之外：

- 到 1 亿的进度环、现在资产、还差多少
- 本月投入 vs 40 万目标 + 连续达标 streak
- 资产推移图（评价额 vs 投信投入元本 —— 两者的差就是运用益）
- 各账户内訳、月次投入柱状图
- **What-if 滑杆**：拖动月投入额，立刻看到达成日期怎么变
- **蒙特卡洛扇形图**：2000 次模拟的 10〜90 百分位，而不是一条假装确定的直线
- 里程碑（2000万 / 3000万 / 5000万 / 7500万 / 1億）
- Coast FIRE 线：攒到多少之后，即使停止投入也能靠复利到达目标

### 有意写在页面上的几件事

- 7% 是**美元计价的名目收益**，日元投资者会直接吃到 USD/JPY 的波动
- 特定口座的收益要交 **20.315%** 税，1 亿是税前还是税后，结论差很多
- **NISA 生涯投资枠 1800 万**的使用率（从邮件里的「口座区分」自动统计）
- 持株会意味着**工资和股票押在同一家公司**上

## Track 2 · Apps Script 安装步骤

### 1. 建项目并推送代码

```bash
npm install -g @google/clasp
clasp login
clasp create --type sheets --title "1億円プロジェクト" --rootDir src
clasp push
```

`--type sheets` 会**同时**建好表格和绑定在它上面的 Apps Script 项目，
所以不用另外建表。`clasp create` 生成的 `.clasp.json` 已在 `.gitignore` 里，不会被提交。

### 2. 设置脚本属性

Apps Script 编辑器 → 左侧齿轮「プロジェクトの設定」→ 最下方「スクリプト プロパティ」：

| 属性名 | 值 | 必填 |
|---|---|---|
| `BITFLYER_API_KEY` | bitFlyer 的 API key | 否（不填就跳过 BTC） |
| `BITFLYER_API_SECRET` | bitFlyer 的 API secret | 否 |
| `SPREADSHEET_ID` | 表格 ID | 否 |

`SPREADSHEET_ID` 只有在你想让脚本写到**别的**表格时才需要填 ——
上一步建的是绑定脚本，默认就写在自己那张表里。

**bitFlyer 的 key 只勾「資産」这一项权限**，不要给下单和出金权限。
这些值只存在脚本属性里，不会进 git。

### 3. 初始化并导入历史

在 Apps Script 编辑器里依次运行：

```
setupSheets()     // 建表 + 写入账户和 6 支基金的主数据
backfillAll()     // 回溯抓取全部历史邮件
```

`backfillAll()` 会读取你收件箱里**约 201 封基準価額メール（2025年10月起）**和
**18 封約定メール（2025年6月起）**，所以看板一开始就有约一年的真实曲线，不是从零开始。

> 第一次运行会弹出授权。脚本需要 `https://mail.google.com/` 这个范围，
> 因为 Apps Script 的 `GmailApp` 只认这个 scope（没有更细的只读版本可用）。
> 代码只做 `GmailApp.search()` 和读取正文，不发送、不删除。

### 4. 校准口数（重要）

約定メール里只有**购入金额**，没有口数，所以口数是用当日基準価額反推的，会有微小误差。

登录楽天証券 → 保有商品一覧 → **CSVで保存**，把文件内容整段粘贴到看板底部的
「保有商品一覧 CSV」框里提交。之后口数以 CSV 的实际值为准，误差归零。
同时会用 CSV 里的取得金额校正元本基准。

> CSV 的列名如果和预期不符会报错并提示，这时把实际的表头行发我，我调一下
> `src/Holdings.gs` 里的 `QTY_HEADERS` / `NAME_HEADERS`。

### 5. 部署为 Web 应用

Apps Script 编辑器 → 右上「デプロイ」→「新しいデプロイ」→ 类型选「ウェブアプリ」：

- **次のユーザーとして実行**：自分
- **アクセスできるユーザー**：**自分のみ** ← 一定要选这个，否则知道 URL 的人能看到你的资产

### 6. 装定时器

运行 `installTriggers()`：

| 触发器 | 时间 | 作用 |
|---|---|---|
| `dailyIngest` | 每天 8:00 JST | 抓邮件、更新股价/BTC、记录快照 |
| `sendWeeklyReport` | 每周一 8:00 JST | 本周进度 + 本月还差多少 |
| `sendMonthlyReport` | 每月 1 日 9:00 JST | 上月结算：达标与否、streak、到达日期变化 |

表格打开后菜单栏也会多出「1億円プロジェクト」，可以手动触发这些操作。

## 日常使用

平时**什么都不用做**——邮件会自动进来。只有两件事需要你动手：

1. 每季度更新一次持株会和ゆうちょ的余额（超过 60 天会在看板上标红）
2. 用现金单独买了个别股票时，在「メールに出ない投入」里补一笔，
   否则月投入额会被低估

## 开发

```bash
npm test        # 49 项测试：解析器、预测模型、浏览器兼容性、打包产物的估值逻辑
clasp push      # 推送到 Apps Script
```

测试用的是**从收件箱里取出的真实邮件正文**，覆盖了几个实际会踩的坑：

- 全角/半角混排（`eMAXIS　Slim　米国株式（Ｓ＆Ｐ５００）` 要能匹配上 `eMAXIS Slim 米国株式(S&P500)`）
- 一封邮件里有多支基金（2026年5月那封同时有オルカン和FANG+，金额和口座区分各不相同）
- HTML 表格和纯文本两条解析路径结果必须一致
- 12 月下单、1 月成交的跨年日期
- 幂等性：同一封邮件重复处理不会重复记账
- `Shared.gs` 在没有任何 Apps Script 全局变量的环境里能跑（Artifact 的前提）
- 表格解析保持列位置：`| ゆうちょ_残高 |  | 円 |` 的空值不能把「円」读成金额

### 文件结构

```
src/
  Shared.gs      ★ 两个版本共用：日期、NFKC 归一化、邮件/表格解析、预测计算
                   不依赖任何 Apps Script API，浏览器里可直接跑（有测试守住）
  Config.gs      Apps Script 专用：设置与 Sheets 读写
  Schema.gs      建表与主数据（账户、6 支基金、股票、BTC）
  Ingest.gs      Gmail 抓取与幂等写入
  Market.gs      GOOGLEFINANCE 中继 + bitFlyer HMAC 签名
  Holdings.gs    CSV 校准、手动余额
  Snapshot.gs    每日估值与历史曲线重建
  Projection.gs  FV / 到达月数 / 必要月投入 / Coast FIRE
  Coaching.gs    落后年数、streak、里程碑、NISA 使用率
  Notify.gs      周报与月报邮件
  Triggers.gs    定时器与表格菜单
  WebApp.gs      Web 应用入口与前端 API
  ui/            看板前端（Chart.js）

artifact/        Track 1 的页面源码
  app.js         连接器调用、同步、估值、渲染
  style.css      样式
  template.html  外壳
tools/
  build-artifact.js   把 Shared.gs + app.js 打包成单文件 HTML
```
